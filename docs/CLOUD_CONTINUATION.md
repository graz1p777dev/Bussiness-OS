# Продолжение Business OS в Codex Cloud

Репозиторий: https://github.com/graz1p777dev/Bussiness-OS
Ветка: codex/dialog-templates. Использовать её последний коммит, не main.

## Задача

Продолжить разработку полного рабочего frontend Business OS. Требования и статусы находятся в TASKS.md, включая 20 разделов большой переработки связанной OS. Изучить существующую структуру, реализовывать последовательно, переиспользовать компоненты. Не ограничиваться добавлением пунктов меню.

Начать с единого settings.json и общей модели связанных сущностей: клиент, диалог, сделка, продажа, чек, товар, запись, задача, сотрудник и AI-событие. Сейчас сделки частично выполняют роль клиентов, а продажи товароучёта не содержат полноценной связи customerId. Сохранить существующие данные через миграцию, а не сбрасывать их.

Затем связать CRM/POS/клиентов/товары/аналитику/календарь; реализовать глобальный Assistant с несколькими чатами и разрешёнными tools, AI-доску и временных агентов, Planning, Store с явными permissions, MCP UI и документацию. Полная детализация и критерии — TASKS.md.

## Границы и правила

- Пока только frontend с локальным сохранением. Реальные модели, интеграции, MCP server, периодическое выполнение, внешние сообщения и продакшен-исправления не выдавать за работающий backend. Записывать их логику в docs/BACKEND_HANDOFF.md.
- Записывать каждую новую просьбу в TASKS.md; ставить [x] только после проверки всей задачи. Общая переработка ещё не реализована.
- Пользователь смотрит локальную версию main на 5173. Не менять main и не развёртывать новую версию вместо неё. Разработка изолирована в codex/dialog-templates.
- Не публиковать сайт: пользователь запросил именно облачную работу Codex.
- Все действия и данные доступны согласно RBAC, включая AI tools, поиск, exports, импорт настроек и переходы между модулями. Read-only должен запрещать мутации в обработчиках, а не только скрывать кнопки.
- Нативные select заменить существующими оформленными компонентами. Выбираемые параметры выбирать, не вводить текстом. Анимации с поддержкой режима слабого компьютера.
- Выполненный AI frontend показывает честный локальный анализ/симуляцию, не изображает подключённую внешнюю модель.
- Пользователь разрешил субагентов Astra с ultra reasoning. При недоступности этого режима сообщить; не заявлять его использование без фактического запуска.
- Минимальные необходимые изменения, существующий стиль, без несогласованного удаления кода.

## Запуск в облачной среде

Установить зависимости через npm ci. Рабочие команды: npm run dev, npm test, npx tsc --noEmit --incremental false, npm run build. Использовать поддерживаемую Node-версию из проекта; тесты используют --experimental-strip-types. Итог оформлять в проверенную ветку/PR, не сливать автоматически в main.

Облачная среда не имеет доступа к браузерному localStorage пользователя и исходным папкам на его ПК/VPS. Не утверждать, что эти данные перенесены. Перенесены исходники, тесты и заметки. Если нужны дополнительные исходные данные, запросить их конкретно.
